# SPEC: Arquitetura Zero Trust com Dual-Token (Substituição do HMAC)

**Objetivo:** Alterar o mecanismo de segurança para integrações entre API Rest e MCP (Model Context Protocol).
**Status:** Aprovado para Implementação.
**Decisão Arquitetural:** Descontinuação do uso de HMAC (Context Binding) em favor da arquitetura **Dual-Token** (User Context Forwarding + Machine M2M Token) no ecossistema .NET 8.

## 1. Contexto e Motivação
O modelo anterior considerava o uso de HMAC para validação da máquina somado ao token do Azure AD B2C para o contexto do usuário. Devido à complexidade operacional e riscos de gerenciamento de chaves simétricas, a arquitetura evoluiu para o padrão **Dual-Token**.
Como o Azure B2C não suporta nativamente *Token Exchange* (OBO), a API Rest exigirá dois JWTs simultâneos para rotas do MCP:
1. `Authorization: Bearer <Token_B2C_Usuario>` (Identidade de Dados).
2. `X-Machine-Token: Bearer <Token_M2M_MCP>` (Identidade de Rede/Máquina).

Esta SPEC define a blindagem de segurança para garantir o isolamento total entre o tráfego do Portal Web (legado) e do MCP.

---

## 2. Configurações de Ambiente (Whitelist)
A validação de `Audiences` e `Client IDs` deve ser baseada no padrão *Options* e arrays para suportar múltiplos plugins/ambientes.

**`appsettings.json` (Exemplo de Estrutura):**
```json
{
  "SecuritySettings": {
    "B2CIssuer": "[https://seu-b2c.b2clogin.com/tenant/v2.0/](https://seu-b2c.b2clogin.com/tenant/v2.0/)",
    "PortalClientId": "client-id-portal-web",
    "McpUserClientId": "client-id-mcp-plugin",
    "McpAllowedMachineClientIds": [
      "client-id-m2m-chatgpt",
      "client-id-m2m-claude"
    ]
  }
}
